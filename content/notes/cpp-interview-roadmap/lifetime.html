3. 存储与生命周期

3.1 作用域、存储期与生命周期

作用域规定名字在源码中的可见范围；存储期规定承载对象的存储保留多久；生命周期规定对象何时建立与销毁。保存一个地址不会自动延长目标对象的生命周期。

存储期
种类典型对象管理方式
自动存储期普通局部对象离开相应作用域时自动销毁。
静态存储期全局变量、static 变量存储贯穿程序执行；初始化时机取决于具体规则。
线程存储期thread_local 对象每线程独立实例，存储与线程相联系。
动态存储期new 创建的对象由 delete 或资源拥有者安排清理。

栈与堆是常见存储实现：栈用于维护函数调用及部分局部数据；堆用于动态分配。分配器负责取得和归还存储。局部 vector 对象通常具有自动存储期，它的元素则由分配器动态保存；局部变量也可能放在寄存器中或被优化消除。

3.2 new、delete 与原始存储

new 表达式：取得合适存储 → 初始化对象 → 返回指针。delete 表达式：销毁对象 → 释放存储。operator new 主要负责分配，不能与完整 new 表达式混为一谈。

分配与释放配对

new Tdelete p是
new T[n]delete[] p是，针对数组元素
mallocfree否，只管理原始存储

失败处理：普通 new 分配失败时通常抛出 std::bad_alloc 异常；malloc 和 new (std::nothrow) 的分配失败返回空指针。若已分配存储但对象构造失败，通常调用匹配的释放函数归还存储。

placement new 用 new (buffer) T(args) 在已有字节空间中构造对象，不再另找存储。调用者须保证大小和对齐，并分别安排对象析构与存储归还。普通 delete/free 可接受空指针，但不能重复释放，也不会把其他指针副本自动清空。

3.3 空指针、野指针与悬垂指针

判断指针能否使用，要分别确认它是否初始化、是否指向目标，以及目标是否仍然有效。“野指针”是工程中的俗称，使用范围并不统一；这里用它特指未初始化或没有建立合法指向的指针，并把目标失效后的指针单独称为悬垂指针（悬空指针）。

三种指针状态
状态产生方式使用边界与处理
空指针int* p = nullptr;，明确表示没有目标。可判空、赋值；不能解引用。初始化为空让“尚无目标”成为明确状态。
野指针函数内普通局部变量 int* p; 未初始化，或从无效地址构造指针。C++17 下，读取这种未初始化指针的值就可能已是 UB，不能先用 if (p) 验证。先初始化或建立合法指向。
悬垂指针 / 引用曾指向有效对象，随后对象离开作用域、被释放，或因容器操作失效。不能继续访问原目标；借用期须受拥有者生命周期和容器操作约束。

判空不等于验证生命周期。释放对象不会自动清空各处保存的地址；把一个指针设为 nullptr，也不会修改其他指针副本。不要通过读取或比较已经失效的指针来证明对象仍存在。

经典问题：delete 后设为 nullptr，为什么仍可能发生释放后使用？

其他别名可能仍保存旧地址。置空只更新当前变量；修复还需让所有借用在对象销毁前结束，或通过仍有效的拥有者重新取得访问入口。

3.4 悬垂引用与非拥有型视图

上一节的悬垂问题同样适用于引用和视图。返回局部对象引用、释放后继续用旧指针、容器重分配后使用旧引用，都需要从目标生命周期解释。

string_view用起点和长度描述字符范围，不复制、不拥有字符。std::string_view v = std::string("abc"); 中的临时 string 在语句结束后销毁，v 随即悬垂。

临时对象通常在创建它的完整表达式结束时销毁，例如上一例的分号处。直接写 const std::string& r = std::string("abc"); 可将该临时对象的生命期延长到 r 的生命期；这个效果不能靠后续引用继续传递，也不适用于返回局部对象引用。

经典问题：为什么返回一个指向局部 string 的 string_view 会出错？

局部 string 返回前被销毁，string_view 不拥有字符，之后访问其中字符已不合法。应返回拥有数据的 string，或保证底层拥有者覆盖视图的全部使用期。
