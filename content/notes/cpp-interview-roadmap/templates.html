6. 模板、类型推导与可调用对象

先理解模板推导和可调用对象，再阅读下一章的容器与算法；转发引用建立在值类别和移动语义之上。

6.1 模板定义、实例化与特化

模板把类型或值留作参数，用同一份描述生成不同版本。例如 template<class T> T add(T a, T b) 可用于 int 或 double。把具体参数代入并形成相应版本，称为实例化；编译器先检查不依赖参数的部分，再检查实例中的类型相关操作。

定义可见性：隐式实例化通常需要看到模板定义，所以常放头文件。类型集合固定时，可在实现文件中显式实例化指定版本，但不会自动支持任意新类型。

特化为特定模板参数另写规则：全特化固定全部参数，如 Box<int>；偏特化匹配一类参数，如 Box<T*>。类模板支持两者，函数模板只能全特化，部分情况通常用重载区分。生成多个版本可能增加编译时间和代码体积。

经典问题：模板为什么通常在头文件里给出定义，而普通函数可以只给声明？

普通函数可先按声明生成调用，链接时找到已有实现；模板可能需要为新类型生成实例，因此通常要看到定义。也可显式实例化一组固定类型。

6.2 auto、decltype 与 decltype(auto)

auto 让编译器从初始化表达式推导变量类型；decltype 获取表达式或指定实体的类型，不执行该表达式。两者规则不同，尤其要留意引用与 const 是否保留。

类型推导
形式规则
auto x = expr按值推导，通常去掉引用和顶层 const；保留指针目标的 const。
auto& x = expr保留引用语义，目标的 const 也保留。
decltype(name)对未加括号的变量名/成员访问，取得实体声明类型。
decltype(expr)（其他表达式）左值得到 T&，将亡值得到 T&&，纯右值得到 T。
decltype(auto)对初始化或返回表达式应用 decltype 规则。

括号会改变结果：n 为 int 变量时，decltype(n) 是 int，decltype((n)) 是 int&。返回局部对象时，decltype(auto) 与 return (local); 可能产生悬垂引用。

std::is_same_v<A,B> 判断两个类型是否相同；static_assert 在条件为假时让编译报错，适合验证推导规则。

6.3 转发引用与 std::forward

转发引用用于接收并保留调用者的左值/右值性质。典型写法是函数模板参数 T&&，其中 T 需要由实参推导，且 T 本身未加 const/volatile：传入 X 左值时 T 推导为 X&，传入 X 右值时 T 为 X。

引用折叠处理类型替换后叠加的引用：有 & 就得到左值引用，只有两层都是 && 才得到右值引用。因此左值传入时，T&& 最终成为 X&。函数内的参数名仍是左值；std::forward<T> 根据推导出的 T，把左值继续当左值，把原右值转回右值再传出。

template<class T>
void relay(T&& value) {
    receive(std::forward<T>(value));
}

易错点：const T&& 不是上述转发引用；类模板中已固定 T 的普通成员参数 T&& 也不是。一律使用 move 会把调用者左值也转为右值。

代码示例：包装函数保留左值与右值调用
经典问题：模板包装函数里，为什么直接传参数名会丢失右值性质？

命名参数在表达式中是左值。forward 利用模板推导保留的信息恢复原值类别；直接使用名字会丢失右值性质，一律 move 又会错误地转换左值。

6.4 Lambda 与捕获

Lambda 是就地定义函数的表达式，形如 [捕获](参数) { 函数体 }。编译器生成可用 () 调用的对象，称为闭包；值捕获把外部数据复制进闭包，引用捕获只借用。[=] 默认按值捕获用到的局部变量，[&] 默认按引用捕获。

常见捕获
形式含义与生命周期
[x]保存 x 的副本；默认调用运算符为 const，mutable 允许修改闭包内副本。
[&x]借用 x，不延长其生命周期。
[this]保存当前对象的指针，不拥有对象。
[*this]（C++17）复制当前对象；须满足复制要求。
[p = std::move(owner)]（C++14）初始化捕获，可把独占资源移入闭包。

生命周期：引用捕获和 this 捕获不延长目标生命期；C++17 的 [=] 捕获 this 也只保存指针。std::function 用统一函数签名包装不同可调用对象，但 C++17 要求目标可拷贝；捕获 unique_ptr 的闭包通常不满足这一点。

常用能力
工具用途与边界
if constexpr（C++17）在模板中按常量条件选择分支，不实例化已确定丢弃的分支；不能用它在非模板代码中隐藏任意非法代码。

后续标准：span、ranges、expected 与协程

span（C++20）用起点和长度借用连续元素；ranges（C++20）让算法直接操作范围，部分 views 在取元素时才计算筛选、变换结果。它们仍受底层对象生命周期限制。expected<T,E>（C++23）保存成功值 T 或错误 E。

协程（C++20）能挂起并从保存位置恢复，所需状态由协程帧保存；它不自动创建线程，也不自带异步 I/O 调度器。

6.6 SFINAE 与模板约束

SFINAE 即“替换失败不是错误”。编译器把推导出的类型代入函数声明时，若参数/返回类型等规定位置无法成立，就移除这个候选，继续找其他匹配。例如要求 T::value_type 的声明，对没有该成员的 int 可以替换失败；函数体内部的任意错误不会因此被忽略。

enable_if_t<条件, T> 在条件为真时得到 T，为假时没有相应类型，可用来触发上述候选排除。示例用 is_integral_v 检查是否为整数类型。C++20 的 concepts/requires 则直接声明模板必须满足的条件，例如支持某个操作，不满足时不参与相应匹配。
