2. 类与对象模型

2.1 类、封装与 this

类是用户定义的类型，把数据成员和成员函数组织在一起。封装通过访问控制维护对象必须满足的条件（不变量），例如余额不得为负。

public 允许外部访问；private 限制为本类及友元访问；protected 还允许派生类按规则访问。友元是用 friend 授予访问权限的指定函数或类。struct 默认 public，class 默认 private，默认继承访问也有这个差别。

  • 非静态成员与 this：每个对象有自己的数据成员；this 是成员函数内指向当前调用对象的指针，this->x 访问该对象的 x。
  • static 成员：数据成员由同一类共享；成员函数没有 this，不能直接访问某个对象的非静态成员。
  • 构造函数：与类同名、无返回类型，在对象建立时初始化状态；冒号后的初始化列表指定基类和成员怎样初始化。
  • 析构函数：写作 ~T()，在对象销毁时执行清理。

const 成员函数在参数列表后写 const，表示不通过 this 修改普通成员。mutable 成员例外：可在这种函数中修改，常用于不改变对象逻辑值的缓存；仍需自行保证线程安全。

2.2 继承与基类子对象

继承让派生类在基类基础上扩展。派生对象内包含基类那一部分状态，称为基类子对象。公开继承表示可按基类接口使用派生对象；基类可访问且无歧义时，派生类指针/引用可转换为基类指针/引用。组合则把另一个类型的对象作为成员，表达“包含”关系。

静态类型是编译时看到的类型，动态类型是实际完整对象的类型。Base& ref = derived; 中，ref 的静态接口是 Base，实际对象可以是 Derived。非虚成员按静态类型选择；要让同一接口随实际类型选择实现，需要后面的虚函数机制。

虚继承用于共享基类子对象。例如 B、C 都继承 A，D 又继承 B、C，形成菱形；若 B、C 都用 virtual 继承 A，D 中只有一份共享的 A，称为虚基类子对象，由最派生类 D 初始化。

2.3 构造与析构顺序

构造顺序：虚基类（由最派生类初始化）→ 直接非虚基类（声明顺序）→ 非静态成员（声明顺序）→ 构造函数体。初始化列表的书写顺序不改变这一规则。

正常析构：先执行当前类析构函数体，再逆序销毁成员和基类。构造失败时，完整对象的析构不会执行，但已构造的成员和基类会清理。

初始化与赋值：引用、const 标量及无可用默认构造的成员，须在进入构造函数体前得到合适初始化。函数体中的赋值不能替代这一步。

2.4 虚函数与动态绑定

虚函数用 virtual 声明，允许派生类为同一接口提供新实现，这称为覆盖。通过基类指针或引用调用时，按实际对象类型选择相应实现，称为动态绑定；同一接口呈现不同行为，就是这里的运行时多态。覆盖函数即使不再写 virtual，仍然是虚函数。

struct Base {
    virtual const char* name() const { return "Base"; }
    virtual ~Base() = default;
};
struct Derived : Base {
    const char* name() const override { return "Derived"; }
};
Derived d;
Base& ref = d;
ref.name();        // "Derived"：动态绑定
ref.Base::name();  // "Base"：显式限定，抑制虚分派

常见实现机制：虚表（vtable）保存虚函数入口等分派信息；对象中的虚指针（vptr）指向适用虚表。一次典型虚调用的过程是：

  1. 编译期根据静态接口确定要调用的虚函数。
  2. 运行时从目标对象取得适用的虚表信息。
  3. 找到该虚函数对应的入口，以正确的对象地址调用覆盖实现。

同类完整对象通常共享适用的虚表；多继承可能需要多个虚指针和 this 地址调整。ABI 是对象布局、传参等二进制接口约定，虚表细节依 ABI 而定。标准规定调用结果，不强制虚表布局；编译器能确定目标时可省掉查表，直接调用，称为去虚拟化。

先掌握这里的调用规则；读完对象布局后，可继续看具体虚表表项与多继承调用示意。

override 让编译器检查是否真的覆盖了基类虚函数，例如漏写成员函数末尾的 const 会导致不匹配。final 禁止该虚函数继续被覆盖，也可放在类上禁止继续派生。

纯虚函数写作 virtual void f() = 0;，表示留待具体派生类实现的接口。仍有纯虚函数没有得到具体覆盖实现的类是抽象类，不能直接创建对象；= 0 不是把函数地址设为空。

覆盖的匹配规则与默认实参

函数参数以及末尾的 const/volatile、引用限定须匹配。引用限定写在成员函数末尾，用 & 或 && 限制调用对象的值类别，见值类别与引用。返回类型通常相同，也允许符合条件的类指针或引用由基类类型变为派生类型，称为协变返回；对象值或智能指针不适用。

默认实参在编译时按静态声明补齐，函数实现才参与动态分派。因此经 Base* 调用时，即使执行 Derived 的实现，省略的参数也取自 Base 的声明。

参考：虚函数规则、Itanium C++ ABI。

经典问题：基类引用的类型不变，为什么能调用不同派生实现？

静态类型决定可调用的接口，动态类型决定虚调用的最终覆盖函数。去掉 virtual 后，该调用按静态类型选择；显式限定基类函数名也会抑制这次虚分派。

2.5 虚析构与构造析构期间的虚调用

经基类指针删除派生对象：在本文 C++17 范围内，基类析构必须为虚函数，否则行为未定义。允许这种销毁方式的接口通常使用 public 虚析构；禁止这种方式时，可用 protected 非虚析构。

构造/析构期间的虚调用只分派到当前正在构造/析构的类层次，不进入尚未构造或已经销毁的派生部分。构造函数本身不能声明为 virtual。纯虚析构仍须提供函数体，因为销毁派生对象时仍会执行基类析构。

经典问题：通过基类指针删除派生对象，为什么需要虚析构？

虚析构使销毁从正确的动态类型启动，再逐层清理基类部分。缺少虚析构却经基类指针 delete 派生对象是未定义行为，不能概括为“只调用基类析构”。

经典问题：非静态成员函数不读取字段，能否通过空指针调用？

不能。非静态成员调用本身就要求有效对象；一次未崩溃的运行不能证明它合法。无对象需求的操作应使用静态成员或普通函数。

2.7 对象切片

对象切片：Derived d; Base b = d; 只复制基类部分，b 是独立的 Base 对象。需要保留多态行为时，使用引用或合适的指针，不能按值放入 vector<Base>。

2.8 对象布局、对齐与 sizeof

对齐要求对象起始地址满足特定倍数，例如 alignof(int) == 4 时地址须是 4 的倍数。编译器在成员间插入填充以满足各自对齐，并在尾部补齐，使数组中下一个对象也正确对齐。offsetof(S, i) 查询成员 i 相对 S 起点的字节偏移，须用于符合布局要求的类型。

例如在 char 大小/对齐为 1、int 为 4、short 为 2 字节且采用默认布局的常见 ABI 下，struct S { char c; int i; short s; }; 常见成员偏移为 0、4、8，总大小为 12。具体结果须结合类型布局和 ABI，用 sizeof、alignof，以及适用类型的 offsetof 验证。

注意：sizeof 通常不求值其表达式操作数；string/vector 的对象大小不包含其全部动态存储。调整成员顺序可能减少填充，但会改变 ABI；压紧布局（packing）限制成员对齐以减少填充，也可能带来未对齐访问和性能问题。

#pragma pack 是编译器扩展，push/pop 用于限制影响范围。压紧布局不等于可安全地把任意网络字节流转换成对象；还需处理字节序、表示和生命周期。未对齐成员的地址不能当作天然满足 int 对齐的普通指针使用。

2.9 虚表布局与多继承调用

下面采用遵循 Itanium C++ ABI 的常见 x86-64 布局，假设启用 RTTI、没有虚继承；这不是所有编译器通用的内存格式。RTTI 是运行时类型信息，供 dynamic_cast 等机制识别实际类型。示意省略普通数据成员与填充，表中的位置相对于虚指针指向的地址点（address point）。

单继承：源码中的 Base 先声明虚函数 f，再声明虚析构；Derived 覆盖 f。一个构造完成的 Derived 对象，其 Base 部分使用指向 Derived 虚表的 vptr：

Derived 对象
  Base 部分的 vptr ───────────┐
                             │   Derived 的虚表
                             │   [-2] offset-to-top = 0
                             │   [-1] typeinfo for Derived
                             └─→ [ 0] Derived::f
                                 [ 1] Derived 完整对象析构入口
                                 [ 2] Derived 删除析构入口

读表要点：vptr 指向地址点，不一定指向整张表开头；offset-to-top 表示从当前基类部分回到完整对象的位移。该 ABI 将虚析构分成“销毁完整对象”和“销毁后再释放存储”两个入口，并不表示执行两次析构。覆盖替换对应入口，新增虚函数可增加表项。

多继承：源码中 Joined 同时继承 Left 和 Right，并覆盖 left、right。以下以 Left 为主基类、Right 位于正偏移 d 的布局为例；两个入口最终访问同一个 Joined 对象。

Joined 对象
  +0  Left 部分  [vptr] ─→ 主虚表地址点
  +d  Right 部分 [vptr] ─→ 次虚表地址点

主虚表：offset-to-top = 0，typeinfo = Joined
次虚表：offset-to-top = -d，typeinfo = Joined

Right* p = &joined;     // 指向 +d 处的 Right 部分
p->right()
  → 次虚表中的 right 入口
  → thunk：把 this 从 Right* 调整回 Joined*
  → Joined::right()

thunk 是调整参数后再跳转到实现的短入口。固定偏移取决于实际布局；虚继承还可能使用额外的虚基类偏移和虚调用偏移，不能直接套用上图。构造/析构期间也不能假定始终使用最终派生类的虚表，调用规则见虚析构与生命周期阶段。

2.10 类型转换、explicit 与 nullptr

类型转换改变值的表示或访问对象的类型。编译器自动完成的转换称为隐式转换；程序员用 cast 等写出的称为显式转换。继承层次中，派生转基类叫向上转型，基类转派生叫向下转型。

显式转换
操作用途与限制
static_cast常规类型转换、向上转型等；向下转型不做运行时类型检查。
dynamic_cast多态层次的运行时检查；常见向下/交叉转换需要多态源类型。指针失败返回空，引用失败抛 bad_cast。
const_cast调整 const/volatile 限定；不使原本 const 的对象变得可写。
reinterpret_cast低层次表示/指针转换；不自动保证后续访问符合对齐、类型与生命周期规则。

含有或继承虚函数的类是多态类型。dynamic_cast 利用运行时类型信息（RTTI）检查转换是否符合实际对象的继承关系；交叉转换是在同一完整对象的不同基类部分之间转换。

explicit 限制某些隐式转换：explicit T(int) 允许 T t(3)，阻止 T t = 3。nullptr 是专用空指针值；在 f(int) 与 f(int*) 重载中，f(0) 选整数版本，f(nullptr) 选指针版本。
