8. 并发与同步

本章关注 C++ 的同步保证和接口用法；线程如何调度、锁如何阻塞与唤醒，见进程与线程及锁与 futex。

8.1 数据竞争与同步关系

线程是程序中的一条执行路径，多条线程可以访问同一对象。典型数据竞争是：不同线程访问同一内存位置，至少一次写入、至少一次不是原子操作，而且缺少同步建立的先后关系；这属于 UB。

happens-before（先行发生）是语言用来保证访问先后与可见性的关系，不是肉眼观察到的时间先后。它可由线程内顺序和锁、join 等同步操作连接起来；例如线程完成后，另一线程成功 join 再读取它写好的结果。对象还必须活到最后一次访问之后。

同步工具：互斥锁让一组操作由单个线程独占执行；原子操作把一次访问或读改写作为不可分割的操作；条件变量让线程等待某个共享条件。单个计数安全，不表示“余额与库存同时更新”这类多对象规则也自动安全。

8.2 thread、join 与 detach

std::thread 对象管理与执行线程的关联。成功构造 std::thread worker(f); 后，f 在新线程执行；线程函数结束和管理对象完成清理是两件事。

8.3 互斥锁、临界区与死锁

互斥锁一次只允许一个线程持有，锁内操作共享状态的范围称为临界区。对同一 mutex 的解锁与后续成功加锁建立同步，使先前写入可见。所有冲突访问都须遵守这套规则，不能只给写入方加锁。

RAII 锁管理
类型适用情况
lock_guard简单作用域持锁，析构时解锁。
unique_lock支持延迟加锁、手工解锁与移动；用于条件变量等待。
scoped_lock（C++17）可同时管理多把锁，采用避免相互锁定死锁的加锁方式。

死锁是参与者互相等待而无法继续，例如线程一持 A 等 B、线程二持 B 等 A。统一加锁顺序，或用 scoped_lock 一起取得需要的不同锁，可避免这类循环等待。recursive_mutex 只允许同一线程重复加锁，不能解决不同线程之间的等待环。

经典问题：写入时加了锁，读取时不加锁，能保证共享变量安全吗？

不能只凭写入方持锁保证安全。冲突访问须参与同一同步协议，或由 join 等关系安排先后；读取绕过协议仍可能形成数据竞争。

8.4 条件变量

条件变量用于等待共享状态满足条件，通知本身不保存业务状态。必须将状态与互斥锁配合使用，而不是依赖“恰好收到一次通知”。

  1. 持锁检查谓词，即“队列非空”等布尔条件；不满足时，wait 原子地释放锁并进入等待。
  2. 生产者在同一锁下修改状态，然后通知等待者。
  3. 等待者醒来后重新取得锁并检查谓词；成立才继续，否则再次等待。
cv.wait(lock, [&] { return closed || !queue.empty(); });

重复检查：wait 可能没有对应通知也返回，这叫虚假唤醒；取得锁前条件也可能被其他线程改变。notify_one 唤醒一个等待者，notify_all 唤醒所有等待者，醒来后都要重新竞争锁并检查条件。条件已满足时，即使通知先发生，后来进入 wait 的线程也能直接继续。

唤醒不保证条件成立：可能虚假唤醒，也可能被其他线程抢先改变状态。用 wait(lock, predicate) 在锁内循环检查真实状态。

8.5 atomic、volatile 与内存序

atomic 提供不可分割的读取、写入或读改写。对 atomic 计数，fetch_add/++ 将“读取—加一—写回”作为一次原子操作；count = count + 1 却分成独立读和写，可能丢失更新。volatile 要求保留实现所规定的可观察访问，常用于平台约定的设备寄存器；不提供线程间原子性或同步。

内存序规定线程间能依赖哪些先后与可见性保证。标志本身读写原子，不等于通过这个标志传递的普通数据也自动安全。

主要内存序
内存序保证与用途
relaxed保证该对象的原子操作及相应修改顺序，不为其他普通数据建立发布关系；适用于无额外发布需求的计数等。
release / acquire常见发布方式：acquire 读取相应 release 写出的标志值后建立同步，随后可安全读取发布前写好的普通数据。
acq_rel同时具有 acquire 和 release 的作用，用于原子读改写操作。
seq_cst默认顺序一致操作，增加相关操作的单一总序约束；不自动修复其他未同步普通访问。

发布链：写普通数据 → release 写标志 → acquire 读到相应标志 → 读普通数据。示例中将标志读写都改为 relaxed，会失去保护普通数据所需的同步关系。

原子不等于无锁：有些类型或平台会借助内部锁实现原子操作，可用 is_lock_free 查询；单次操作无锁也不保证整个算法正确。

CAS 与 ABA：只比较当前值的局限

CAS（比较并交换）把当前值与预期值比较，相符才写入新值，整个步骤原子完成。C++ 的 compare_exchange_* 失败时会把当前值写回 expected；weak 版本还可能虚假失败，通常放在重试循环中。

ABA 指值从 A 变成 B 又回到 A，CAS 只看当前值，察觉不到中途变化。例如地址被释放后复用，地址相同却已是另一个对象。版本号可帮助识别变化，还需安全回收方案保证其他读者不会访问已销毁对象。

8.6 shared_ptr 的线程安全

层次规则
共享控制块不同 shared_ptr 实例可各自进行复制、销毁等所有权操作。
同一个 shared_ptr 变量并发读写仍需同步；C++17 可用对应原子自由函数或锁，C++20 可用 atomic<shared_ptr<T>>。
