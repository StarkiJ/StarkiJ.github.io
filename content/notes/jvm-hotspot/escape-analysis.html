HotSpot 对象优化

逃逸、标量替换与锁消除

static final class Pair {
    final int x, y;
    Pair(int x, int y) { this.x = x; this.y = y; }
}
static int sum(int a, int b) {
    Pair p = new Pair(a, b);
    return p.x + p.y;
}

若编译器能看到相关构造与使用、确认不需要保留可观察的对象身份，可把 p.x / p.y 化为独立值，最终只计算 a+b。逃逸分析提供是否逃出方法 / 线程等信息，标量替换是可能采用的变换；分析成功也不保证每种代码形态都能消除分配。写入静态容器、传入无法分析的调用或观察身份，都可能影响决策。

JDK 21 HotSpot C2 的这一优化不能一概表述为“对象从堆搬到栈”。若同步只作用于无法被其他线程访问的对象，编译器也可能消除相应锁操作；正确性依赖分析与语言语义。优化帧还可能需要在反优化时重新物化对象。GC 篇保留分配职责，这里负责解释为何分配会消失。
