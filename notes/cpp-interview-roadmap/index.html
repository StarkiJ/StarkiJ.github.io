1. 语言基础

1.1 类型、对象与变量

类型规定数据如何表示、允许哪些操作；对象是程序中用于存放值、具有类型和生命周期的存储实例。int n = 10; 建立一个 int 对象，用名字 n 访问它，并把初值设为 10。变量可以表示对象，也可以是引用。

int copy = n; 建立独立副本；int& ref = n; 为原对象建立别名；int* ptr = &n; 保存其地址。改变 ref 就是改变 n，改变 copy 则不影响 n。

未定义行为（UB）表示标准不规定程序结果，可能崩溃，也可能暂时表现正常。后文的越界、悬垂等问题都要按这个含义理解。

C++、C 与运行时

C++ 在 C 之外提供类、模板、异常及对象自动管理资源等机制，但并不与 C 完全兼容。原生 C++ 程序通常不要求虚拟机，也不默认由垃圾回收器追踪和回收不再可达的动态对象；分配、异常处理等仍需要运行时支持。

1.2 初始化与赋值

初始化建立对象的初始状态；赋值修改已有对象。类对象的初始化可能调用构造函数来建立状态，之后的赋值则由赋值运算符处理。

列表初始化使用花括号，拒绝可能丢失值的窄化转换。类的非空列表初始化优先考虑 initializer_list 构造函数，即接收一组元素的构造函数。例如可变长数组 vector：vector<int> a(3, 7) 是三个 7，vector<int> b{3, 7} 是两个元素 3 和 7。

默认构造函数可不传实参调用。类若有用户提供的默认构造函数，T{} 不保证其整数、指针等成员全部清零。

1.3 指针、引用与参数传递

指针保存目标地址，&n 取 n 的地址，*p 访问 p 指向的对象；引用为目标建立别名。sizeof 取得类型或对象表示所需的字节数。

参数传递：传值建立独立参数；传指针复制地址，通过地址可以修改目标，但修改形参指针不会改变调用者的指针变量；传引用直接借用调用者对象。需要重设调用者的指针时可传 T*&，也可返回新指针。

接口选择：int、double、指针等小类型常传值；只读大对象用 const T&，表示不通过该参数修改目标；要修改对象用 T&；目标允许不存在时可用 T*，以空指针表示。

1.4 const 与 constexpr

const限制通过该声明修改对象，但初值可以在运行时确定。constexpr 变量要求初值是常量表达式，即可按语言规则在编译时确定的表达式；constexpr 函数既可用于编译期求值，也可在运行时调用。

const 的限定位置
声明限制
const int* p不能通过 p 修改目标；p 可改变指向（底层 const）。
int* const p = &np 不可改变指向；可通过 p 修改非 const 的 n（顶层 const）。
const int* const p = &n指向和通过它对目标的修改都受限。

顶层 const 限定对象本身，例如指针不可改指向；底层 const 限定所指向或引用的目标。const 不递归冻结其他对象，也不提供线程同步；去掉限定后仍不能修改原本为 const 的对象。

1.5 数组、指针与字符串

数组连续保存固定数量的同类型元素；指针不自带元素数量。多数表达式中数组转换为首元素指针，但对数组直接使用 sizeof 时不发生这种转换。函数形参 int a[] 被调整为 int* a。

C 风格字符串用 '\0' 标记结束，长度不含终止字符。const char* p = "Hello"; 指向不可修改的字符串字面量；char text[] = "Hello"; 创建可写副本。C++17 不允许把该字面量赋给 char*。strlen 扫描到终止符，范围内没有有效终止符就可能越界；std::string 则自己保存字符并维护长度。

char text[] = "Hello";       // 6 个字符，包含 '\0'
const char* p = text;
sizeof(text);                // 6：整个数组大小
std::strlen(text);           // 5：终止字符前的长度
sizeof(p);                   // 平台的指针大小，与字符串长度无关

经典问题：为什么 sizeof 数组能取得全部大小，传进函数后却常常不行？

真正的数组在 sizeof 中保留数组类型；void f(int a[]) 的 a 已是指针。需要长度时应显式传入，或使用能表达范围的接口。

1.6 整数提升、转换与溢出

整数提升：char、short 等较窄整数参与许多运算前，若 int 可表示其全部值就提升为 int，否则提升为 unsigned int。计算后存回窄类型，还会发生转换。

溢出规则：N 位无符号算术按模 2N 计算，转换回该无符号类型也按此规则取值，例如转回 8 位无符号类型时，256 变为 0。有符号算术超出类型范围是 UB，不能依赖回绕。std::numeric_limits<T> 可查询类型范围。

混合比较：通常算术转换可能把负数转成很大的无符号值。比较有符号下标与容器 size 时，应先处理负值。容量计算、整数翻转等应在乘加前检查范围。

经典问题：8 位 unsigned char 的 while (i++ <= 255) 为什么无法靠条件结束？

在 8 位 unsigned char 前提下，i++ 返回的旧值始终在 0～255 内，条件一直成立；更新后存回 i 会回绕。若要遍历 0～255，可用能表示 256 的 int：for (int i = 0; i < 256; ++i)。

2. 存储与生命周期

2.1 作用域、存储期与生命周期

作用域规定名字在源码中的可见范围；存储期规定承载对象的存储保留多久；生命周期规定对象何时建立与销毁。保存一个地址不会自动延长目标对象的生命周期。

存储期
种类典型对象管理方式
自动存储期普通局部对象离开相应作用域时自动销毁。
静态存储期全局变量、static 变量存储贯穿程序执行；初始化时机取决于具体规则。
线程存储期thread_local 对象每线程独立实例，存储与线程相联系。
动态存储期new 创建的对象由 delete 或资源拥有者安排清理。

栈与堆是常见存储实现：栈用于维护函数调用及部分局部数据；堆用于动态分配。分配器负责取得和归还存储。局部 vector 对象通常具有自动存储期，它的元素则由分配器动态保存；局部变量也可能放在寄存器中或被优化消除。

2.2 new、delete 与原始存储

new 表达式：取得合适存储 → 初始化对象 → 返回指针。delete 表达式：销毁对象 → 释放存储。operator new 主要负责分配，不能与完整 new 表达式混为一谈。

失败处理：普通 new 分配失败时通常抛出 std::bad_alloc 异常；malloc 和 new (std::nothrow) 的分配失败返回空指针。若已分配存储但对象构造失败，通常调用匹配的释放函数归还存储。

placement new 用 new (buffer) T(args) 在已有字节空间中构造对象，不再另找存储。调用者须保证大小和对齐，并分别安排对象析构与存储归还。普通 delete/free 可接受空指针，但不能重复释放，也不会把其他指针副本自动清空。

2.3 悬垂引用与非拥有型视图

悬垂是访问句柄仍存在，而目标对象已失效。常见来源：返回局部对象引用、释放后继续用旧指针、容器重分配后使用旧引用。

string_view用起点和长度描述字符范围，不复制、不拥有字符。std::string_view v = std::string("abc"); 中的临时 string 在语句结束后销毁，v 随即悬垂。

临时对象通常在创建它的完整表达式结束时销毁，例如上一例的分号处。直接写 const std::string& r = std::string("abc"); 可将该临时对象的生命期延长到 r 的生命期；这个效果不能靠后续引用继续传递，也不适用于返回局部对象引用。

3. 类与对象模型

3.1 类、封装与 this

类是用户定义的类型，把数据成员和成员函数组织在一起。封装通过访问控制维护对象必须满足的条件（不变量），例如余额不得为负。

public 允许外部访问；private 限制为本类及友元访问；protected 还允许派生类按规则访问。友元是用 friend 授予访问权限的指定函数或类。struct 默认 public，class 默认 private，默认继承访问也有这个差别。

  • 非静态成员与 this：每个对象有自己的数据成员；this 是成员函数内指向当前调用对象的指针，this->x 访问该对象的 x。
  • static 成员：数据成员由同一类共享；成员函数没有 this，不能直接访问某个对象的非静态成员。
  • 构造函数：与类同名、无返回类型，在对象建立时初始化状态；冒号后的初始化列表指定基类和成员怎样初始化。
  • 析构函数：写作 ~T()，在对象销毁时执行清理。

const 成员函数在参数列表后写 const，表示不通过 this 修改普通成员。mutable 成员例外：可在这种函数中修改，常用于不改变对象逻辑值的缓存；仍需自行保证线程安全。

3.2 继承与基类子对象

继承让派生类在基类基础上扩展。派生对象内包含基类那一部分状态，称为基类子对象。公开继承表示可按基类接口使用派生对象；基类可访问且无歧义时，派生类指针/引用可转换为基类指针/引用。组合则把另一个类型的对象作为成员，表达“包含”关系。

静态类型是编译时看到的类型，动态类型是实际完整对象的类型。Base& ref = derived; 中，ref 的静态接口是 Base，实际对象可以是 Derived。非虚成员按静态类型选择；要让同一接口随实际类型选择实现，需要后面的虚函数机制。

虚继承用于共享基类子对象。例如 B、C 都继承 A，D 又继承 B、C，形成菱形；若 B、C 都用 virtual 继承 A，D 中只有一份共享的 A，称为虚基类子对象，由最派生类 D 初始化。

3.3 构造与析构顺序

构造顺序：虚基类（由最派生类初始化）→ 直接非虚基类（声明顺序）→ 非静态成员（声明顺序）→ 构造函数体。初始化列表的书写顺序不改变这一规则。

正常析构：先执行当前类析构函数体，再逆序销毁成员和基类。构造失败时，完整对象的析构不会执行，但已构造的成员和基类会清理。

初始化与赋值：引用、const 标量及无可用默认构造的成员，须在进入构造函数体前得到合适初始化。函数体中的赋值不能替代这一步。

特殊成员函数包括默认构造、析构、拷贝构造/赋值和移动构造/赋值。编译器按规则自动提供部分操作；= default 请求默认实现，= delete 明确禁用操作。移动表示转交资源，详见第 5 节。

3.5 虚函数与动态绑定

虚函数用 virtual 声明，允许派生类为同一接口提供新实现，这称为覆盖。通过基类指针或引用调用时，按实际对象类型选择相应实现，称为动态绑定；同一接口呈现不同行为，就是这里的运行时多态。覆盖函数即使不再写 virtual，仍然是虚函数。

struct Base {
    virtual const char* name() const { return "Base"; }
    virtual ~Base() = default;
};
struct Derived : Base {
    const char* name() const override { return "Derived"; }
};
Derived d;
Base& ref = d;
ref.name();        // "Derived"：动态绑定
ref.Base::name();  // "Base"：显式限定，抑制虚分派

常见实现机制：虚表（vtable）保存虚函数入口等分派信息；对象中的虚指针（vptr）指向适用虚表。一次典型虚调用的过程是：

  1. 编译期根据静态接口确定要调用的虚函数。
  2. 运行时从目标对象取得适用的虚表信息。
  3. 找到该虚函数对应的入口，以正确的对象地址调用覆盖实现。

同类完整对象通常共享适用的虚表；多继承可能需要多个虚指针和 this 地址调整。ABI 是对象布局、传参等二进制接口约定，虚表细节依 ABI 而定。标准规定调用结果，不强制虚表布局；编译器能确定目标时可省掉查表，直接调用，称为去虚拟化。

override 让编译器检查是否真的覆盖了基类虚函数，例如漏写成员函数末尾的 const 会导致不匹配。final 禁止该虚函数继续被覆盖，也可放在类上禁止继续派生。

纯虚函数写作 virtual void f() = 0;，表示留待具体派生类实现的接口。仍有纯虚函数没有得到具体覆盖实现的类是抽象类，不能直接创建对象；= 0 不是把函数地址设为空。

覆盖的匹配规则与默认实参

函数参数以及末尾的 const/volatile、引用限定须匹配。引用限定写在成员函数末尾，用 & 或 && 限制调用对象的值类别，见第 5 节。返回类型通常相同，也允许符合条件的类指针或引用由基类类型变为派生类型，称为协变返回；对象值或智能指针不适用。

默认实参在编译时按静态声明补齐，函数实现才参与动态分派。因此经 Base* 调用时，即使执行 Derived 的实现，省略的参数也取自 Base 的声明。

3.6 虚析构与构造析构期间的虚调用

经基类指针删除派生对象：在本文 C++17 范围内，基类析构必须为虚函数，否则行为未定义。允许这种销毁方式的接口通常使用 public 虚析构；禁止这种方式时，可用 protected 非虚析构。

构造/析构期间的虚调用只分派到当前正在构造/析构的类层次，不进入尚未构造或已经销毁的派生部分。构造函数本身不能声明为 virtual。纯虚析构仍须提供函数体，因为销毁派生对象时仍会执行基类析构。

3.7 重载、隐藏与成员调用

3.9 对象布局、对齐与 sizeof

对齐要求对象起始地址满足特定倍数，例如 alignof(int) == 4 时地址须是 4 的倍数。编译器在成员间插入填充以满足各自对齐，并在尾部补齐，使数组中下一个对象也正确对齐。offsetof(S, i) 查询成员 i 相对 S 起点的字节偏移，须用于符合布局要求的类型。

例如在 char 大小/对齐为 1、int 为 4、short 为 2 字节且采用默认布局的常见 ABI 下，struct S { char c; int i; short s; }; 常见成员偏移为 0、4、8，总大小为 12。具体结果须结合类型布局和 ABI，用 sizeof、alignof，以及适用类型的 offsetof 验证。

注意：sizeof 通常不求值其表达式操作数；string/vector 的对象大小不包含其全部动态存储。调整成员顺序可能减少填充，但会改变 ABI；压紧布局（packing）限制成员对齐以减少填充，也可能带来未对齐访问和性能问题。

4. 资源管理与智能指针

4.1 所有权、RAII 与异常安全

所有权说明谁负责最终释放内存、文件、锁等资源；只使用资源而不负责释放的是借用者。RAII（资源获取即初始化）把资源交给对象管理：构造时取得或接管，析构时释放，清理便随对象生命周期自动执行。

异常与栈展开：throw 报告异常，程序沿调用关系向外寻找匹配的 catch。在找到的 catch 执行前，沿途退出的作用域会销毁已构造的局部对象，这称为栈展开。RAII 因而能覆盖正常返回和异常退出。

异常安全保证
级别失败后的要求
基本保证不泄漏资源，对象不变量成立，但值可能改变。
强保证对可观察状态没有影响；可用临时对象完成后再提交。
无抛出保证操作不通过异常报告失败。

noexcept 声明函数不向调用者传出异常；违反时进入 std::terminate 终止处理。析构通常应保持不抛异常，尤其不能在栈展开时再次抛出。RAII 不保证程序被强制终止时仍完成清理。

4.2 unique_ptr：独占所有权

unique_ptr 表达独占所有权：同一份释放责任只交给一个管理者。它保存指针与删除方式，析构时清理；禁止拷贝，允许用移动转交责任，移动后源指针为空。make_unique<T>(args) 构造 T 并返回管理它的 unique_ptr。

4.3 shared_ptr：共享所有权

shared_ptr 允许多个管理者共同拥有一个对象。它们关联一份控制块，记录强拥有者数量和删除方式：拷贝增加计数，移动转交已有计数，销毁或 reset 减少计数；强计数降到 0 才销毁目标。复制管理者不复制目标对象。

控制块不一定与对象同时释放。weak_ptr 是不增加强计数的观察者，仍有它存在时，目标虽已销毁，控制块还需保留。make_shared<T>(args) 创建对象及共享管理关系，通常合并分配以减少开销；这块存储可能等到弱观察者也消失才归还。

重复接管：从同一裸指针独立构造两个 shared_ptr 会产生两份控制块，可能重复释放。需要共享时应复制已有 shared_ptr。

对象如何取得共享自身的指针

类可继承 std::enable_shared_from_this<T>。首个 shared_ptr 建立拥有关系时，会关联对象内部的弱观察状态；之后调用 shared_from_this() 可取得同一控制块的 shared_ptr。不能直接用 shared_ptr(this) 再建一组；构造期间拥有关系通常还未建立，此时调用 shared_from_this() 会失败。

5.1 值类别与引用

表达式是一次求值的语法单位，例如 n、a+b、f()。它既有类型，也有值类别；后者区分是否标识对象、是否可参与资源复用，影响引用绑定与拷贝/移动选择。

6. STL 容器与算法

6.1 容器、迭代器与算法

STL 通常指标准库的容器、迭代器、算法等通用组件。容器保存元素；迭代器表示访问位置，*it 访问元素，++it 前进一步；算法通过这些位置操作元素，不必知道具体容器类型。

范围 [first, last) 包含 first、不包含 last。begin() 指向开头，end() 是不能解引用的尾后位置；空范围二者相等。vector 迭代器支持直接跳到第 n 个位置，list 则沿节点移动；std::sort 要求随机访问迭代器，list 应用自己的 sort 成员。

复杂度：n 是元素数，O 描述工作量随 n 增长的量级。“摊还 O(1)”把一系列操作的总成本平均到每次，不代表每次操作都同样快。

常用容器与适配器

关联容器按键查找元素。map 保存键值对，如姓名到成绩；set 只保存键，常用于判重或成员查询。下列容器中键不能重复，查找依据是键的等价关系。

6.4 迭代器、引用与指针失效

失效表示之前取得的位置不再保证可用，不能继续用它访问元素，常因元素搬迁、销毁或容器内部结构改变。迭代器失效与对象地址失效要分别判断：哈希表重新分桶可能改变遍历结构，却不搬动元素。

最常用的失效规则
容器与操作迭代器元素引用 / 指针
vector 重新分配全部失效，包括旧 end()。全部失效。
vector 插入，未重新分配插入位置及之后失效；尾部插入使旧 end() 失效。插入位置及之后失效；尾部插入不影响已有元素引用。

6.5 push_back 与 emplace_back

push_back 接收一个 T，再拷贝或移动到容器；emplace_back 把参数按原来的左值/右值性质传给构造函数，在新元素位置直接构造 T。传构造参数可省去临时对象；传已有 T 时仍可能拷贝或移动。

emplace 不保证更快。它不消除扩容时旧元素的迁移，也不保证没有分配或异常。转交资源前应先用管理对象建立所有权，避免裸资源在异常路径泄漏。

6.6 范围算法与比较器

谓词是返回真假条件的函数，例如“元素是否为偶数”。算法用它筛选或分组；比较器则判断两个元素的先后关系。

remove/remove_if 将保留元素移至范围前部，返回新逻辑结尾，不改变容器大小。应再调用 erase 删除尾部；remove 后尾部元素的具体值不应作为过滤结果使用。

auto last = std::remove_if(v.begin(), v.end(),
                          [](int x) { return x % 2 == 0; });
v.erase(last, v.end());  // 真正缩小容器

删除遍历：vector 常用 it = v.erase(it) 接回有效位置，不能继续使用已失效的 it。C++20 的 erase_if 可简化适用容器的删除。

严格弱序要求元素不排在自身前面、先后关系可传递，以及“互不先于”的等价关系也可传递。升序可用 a < b；写成 a <= b 会破坏自比较为假的要求。

lower_bound 折半缩小候选范围，寻找第一个不排在目标值前面的元素；普通升序下就是第一个大于等于目标的元素，找不到则返回 end。范围必须满足“排在目标前的元素在前，其余在后”；按同一比较器排序是满足这一前提的常见方式。

#include <algorithm>
#include <cassert>
#include <vector>
struct KV { int key; char value; };
int main() {
    std::vector<KV> v{{2,'a'}, {0,'x'}, {1,'b'}, {2,'c'}, {0,'y'}};
    auto end = std::stable_partition(v.begin(), v.end(),
                                   [](const KV& x) { return x.key != 0; });
    assert(end - v.begin() == 3);
    assert(v[0].value=='a' && v[1].value=='b' && v[2].value=='c');
    assert(v[3].value=='x' && v[4].value=='y');
    std::stable_sort(v.begin(), end,
                     [](const KV& a, const KV& b) { return a.key > b.key; });
    assert(v[0].value=='a' && v[1].value=='c' && v[2].value=='b');
}

7. 模板与类型推导

7.1 模板定义、实例化与特化

模板把类型或值留作参数，用同一份描述生成不同版本。例如 template<class T> T add(T a, T b) 可用于 int 或 double。把具体参数代入并形成相应版本，称为实例化；编译器先检查不依赖参数的部分，再检查实例中的类型相关操作。

定义可见性：隐式实例化通常需要看到模板定义，所以常放头文件。类型集合固定时，可在实现文件中显式实例化指定版本，但不会自动支持任意新类型。

特化为特定模板参数另写规则：全特化固定全部参数，如 Box<int>；偏特化匹配一类参数，如 Box<T*>。类模板支持两者，函数模板只能全特化，部分情况通常用重载区分。生成多个版本可能增加编译时间和代码体积。

经典问题：模板为什么通常在头文件里给出定义，而普通函数可以只给声明？

普通函数可先按声明生成调用，链接时找到已有实现；模板可能需要为新类型生成实例，因此通常要看到定义。也可显式实例化一组固定类型。

7.3 转发引用与 std::forward

转发引用用于接收并保留调用者的左值/右值性质。典型写法是函数模板参数 T&&，其中 T 需要由实参推导，且 T 本身未加 const/volatile：传入 X 左值时 T 推导为 X&，传入 X 右值时 T 为 X。

引用折叠处理类型替换后叠加的引用：有 & 就得到左值引用，只有两层都是 && 才得到右值引用。因此左值传入时，T&& 最终成为 X&。函数内的参数名仍是左值；std::forward<T> 根据推导出的 T，把左值继续当左值，把原右值转回右值再传出。

template<class T>
void relay(T&& value) {
    receive(std::forward<T>(value));
}

易错点：const T&& 不是上述转发引用；类模板中已固定 T 的普通成员参数 T&& 也不是。一律使用 move 会把调用者左值也转为右值。

命名参数在表达式中是左值。forward 利用模板推导保留的信息恢复原值类别；直接使用名字会丢失右值性质，一律 move 又会错误地转换左值。

8. 并发与同步

8.1 数据竞争与同步关系

线程是程序中的一条执行路径，多条线程可以访问同一对象。典型数据竞争是：不同线程访问同一内存位置，至少一次写入、至少一次不是原子操作，而且缺少同步建立的先后关系；这属于 UB。

happens-before（先行发生）是语言用来保证访问先后与可见性的关系，不是肉眼观察到的时间先后。它可由线程内顺序和锁、join 等同步操作连接起来；例如线程完成后，另一线程成功 join 再读取它写好的结果。对象还必须活到最后一次访问之后。

同步工具：互斥锁让一组操作由单个线程独占执行；原子操作把一次访问或读改写作为不可分割的操作；条件变量让线程等待某个共享条件。单个计数安全，不表示“余额与库存同时更新”这类多对象规则也自动安全。

8.2 thread、join 与 detach

std::thread 对象管理与执行线程的关联。成功构造 std::thread worker(f); 后，f 在新线程执行；线程函数结束和管理对象完成清理是两件事。

8.4 条件变量

条件变量用于等待共享状态满足条件，通知本身不保存业务状态。必须将状态与互斥锁配合使用，而不是依赖“恰好收到一次通知”。

  1. 持锁检查谓词，即“队列非空”等布尔条件；不满足时，wait 原子地释放锁并进入等待。
  2. 生产者在同一锁下修改状态，然后通知等待者。
  3. 等待者醒来后重新取得锁并检查谓词；成立才继续，否则再次等待。
cv.wait(lock, [&] { return closed || !queue.empty(); });

重复检查：wait 可能没有对应通知也返回，这叫虚假唤醒；取得锁前条件也可能被其他线程改变。notify_one 唤醒一个等待者，notify_all 唤醒所有等待者，醒来后都要重新竞争锁并检查条件。条件已满足时，即使通知先发生，后来进入 wait 的线程也能直接继续。

8.5 atomic、volatile 与内存序

atomic 提供不可分割的读取、写入或读改写。对 atomic 计数，fetch_add/++ 将“读取—加一—写回”作为一次原子操作；count = count + 1 却分成独立读和写，可能丢失更新。volatile 要求保留实现所规定的可观察访问，常用于平台约定的设备寄存器；不提供线程间原子性或同步。

内存序规定线程间能依赖哪些先后与可见性保证。标志本身读写原子，不等于通过这个标志传递的普通数据也自动安全。

主要内存序
内存序保证与用途
relaxed保证该对象的原子操作及相应修改顺序，不为其他普通数据建立发布关系；适用于无额外发布需求的计数等。
release / acquire常见发布方式：acquire 读取相应 release 写出的标志值后建立同步，随后可安全读取发布前写好的普通数据。

seq_cst默认顺序一致操作，增加相关操作的单一总序约束；不自动修复其他未同步普通访问。

发布链：写普通数据 → release 写标志 → acquire 读到相应标志 → 读普通数据。示例中将标志读写都改为 relaxed，会失去保护普通数据所需的同步关系。

原子不等于无锁：有些类型或平台会借助内部锁实现原子操作，可用 is_lock_free 查询；单次操作无锁也不保证整个算法正确。

CAS 与 ABA：只比较当前值的局限

CAS（比较并交换）把当前值与预期值比较，相符才写入新值，整个步骤原子完成。C++ 的 compare_exchange_* 失败时会把当前值写回 expected；weak 版本还可能虚假失败，通常放在重试循环中。

ABA 指值从 A 变成 B 又回到 A，CAS 只看当前值，察觉不到中途变化。例如地址被释放后复用，地址相同却已是另一个对象。版本号可帮助识别变化，还需安全回收方案保证其他读者不会访问已销毁对象。

代码示例：release/acquire 发布普通数据
经典问题：把共享计数声明成 volatile，就能安全执行多线程 ++ 吗？

不能。volatile 不建立原子性或同步。共享计数可用 atomic 的 fetch_add，或在互斥锁保护下更新；跨多个变量的约束仍需要完整协议。

9. 编译、链接与调试

9.1 翻译单元、声明与定义

典型构建流程：预处理展开头文件和宏 → 编译生成汇编 → 汇编生成目标文件 → 链接成程序或库。一个 cpp 连同包含内容形成翻译单元。链接器按符号记录把函数/变量的引用与定义对应起来，并修正相关地址。

声明说明名字和类型，例如 extern int count;；定义建立变量或提供函数体，例如 int count = 0;。extern 在这里声明别处存在一个变量，不另建一份。ODR（单一定义规则）约束同一实体允许有哪些定义；普通外部链接变量、非 inline 函数通常只应在一处定义。

常见链接错误
错误检查方向
undefined reference / unresolved external symbol实现是否参与构建、依赖库是否链接、声明定义是否匹配、模板是否实例化、工具相关的链接顺序。
multiple definition是否在头文件定义普通外部链接实体并被多个翻译单元包含；是否违反单一定义规则 ODR。

库：静态库通常在链接时提供所需目标代码；动态库通过加载或运行时的动态链接机制使用。两者均需考虑 ABI、版本和依赖，不能仅概括为性能优劣。

多文件示例：共享声明、唯一的定义与模板实例化

counter.hpp

#ifndef NOTE_COUNTER_HPP
#define NOTE_COUNTER_HPP
extern int count;
int tick();
template<class T> T twice(T x) { return x + x; }
#endif

counter.cpp

#include "counter.hpp"
int count = 0;
int tick() { return ++count; }

main.cpp

#include "counter.hpp"
#include <cassert>
int main() {
    assert(tick() == 1);
    assert(count == 1);
    assert(twice(3) == 6);
}
g++ -std=c++17 counter.cpp main.cpp -o demo

counter.hpp 提供声明与模板定义；counter.cpp 提供 count 与 tick 的唯一定义；main.cpp 使用它们并实例化 twice<int>。头文件不独立链接。源码：counter.hpp · counter.cpp · main.cpp。

经典问题：省略 counter.cpp，或把 int count = 0 放进头文件会怎样？

前者缺少 count/tick 的定义，通常链接失败；后者被两个 cpp 包含后产生重复外部定义，违反 ODR。头文件防重不能跨翻译单元去重。若把 twice 的定义移到 cpp，则还需要为使用的类型显式实例化；只留下模板声明不会自动产生任意类型版本。

实践与延伸：程序执行：寄存器、调用与链接。

9.2 static 的不同含义

链接决定不同位置的声明能否指向同一实体：内部链接把实体限制在本翻译单元，外部链接允许跨翻译单元引用；它与名字在源码中是否可见的“作用域”不同。命名空间用于组织名字，如 std::vector 中的 std；文件最外层也属于命名空间作用域。

static 按声明位置解释
位置含义
局部变量静态存储期，名字仍在局部可见；需要动态初始化时首次执行到声明处初始化。
命名空间作用域变量或函数具有内部链接。
类内成员数据成员由同一类共享；成员函数没有 this。C++17 inline static 数据成员可在类内定义。

线程安全：C++11 起局部 static 的初始化具有相应线程安全保证，后续修改不会自动同步。例如多线程调用 static int id = 0; return ++id; 仍可能产生数据竞争。

9.3 inline、ODR 与宏

inline 允许符合 ODR 的定义出现在多个翻译单元中，适合头文件定义，但不强制展开调用。外部链接的 inline 函数仍是同一个函数；多份定义须满足代码记号序列一致、相关名字含义一致等条件，不能让不同 cpp 看到不同函数体。

头文件防重只避免同一翻译单元重复包含，不能替代跨翻译单元的 ODR。普通外部链接函数通常在头文件声明、在一个 cpp 中定义。

宏在预处理时替换代码记号（名称、运算符等）。例如 #define SQUARE(x) ((x) * (x)) 将 SQUARE(i++) 展开为 ((i++) * (i++))；对同一变量的两次自增未定序（互相没有先后约束），导致 UB。加括号不能避免重复求值，普通函数不会这样展开实参。

经典问题：inline 一定会展开函数调用吗？它与头文件定义有什么关系？

不一定展开，编译器决定调用优化。inline 允许满足 ODR 条件的相关定义出现在多个翻译单元；头文件防重只处理单个翻译单元内的重复包含。

9.4 未定义行为与错误定位

常见 UB 来源包括未初始化读取、越界、悬垂、释放后使用、有符号溢出和数据竞争。检测器为程序加入额外检查，在触发相应访问或操作时报告错误；它们只能覆盖支持的错误类型和实际执行路径。

  1. 固定输入和构建配置，区分编译、链接或运行时问题。
  2. 建立最小复现，检查首次故障位置、调用栈（当前函数及逐层调用者）、对象生命周期与访问顺序。
  3. 在支持的平台用 ASan 查内存越界/释放后使用，UBSan 查部分语言错误，TSan 查数据竞争。
  4. 修复根因，用原始复现和必要边界验证；一次未报告不能证明全部路径正确。
经典问题：加一行打印就不崩溃，是否说明已经修好了？

不能。打印可能改变时序、布局或优化，使问题暂时隐藏。应定位非法访问或同步错误并修复，再用原始复现与边界验证。

9.5 性能测量与优化

  • 先定指标：吞吐是单位时间完成量，延迟是一次操作的耗时；二者与内存峰值可能存在取舍。性能分析器（profiler）通过定期采样或加入统计代码，找出耗时和分配集中的位置。
  • 控制变量：固定输入规模与分布、编译器、优化配置，区分初始化和稳态成本，重复测量观察波动。
  • 避免无效基准：保证计算结果可观察，防止循环被消除；不要随意加 volatile，因为它会改变程序的访问约束。
  • 结合场景判断：复杂度描述增长趋势，分配、复制、缓存和锁竞争影响实际成本。reserve 可能减少迁移，也会改变内存占用。

实践与延伸：缓存局部性与性能测量。
