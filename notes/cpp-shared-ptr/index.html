简化 shared_ptr：计数与释放

从控制块和所有权不变量出发，实现拷贝、移动、赋值与资源释放。

1. 控制块与所有权

共享所有权允许多个管理对象共同负责同一个资源；最后一个拥有者离开时释放资源。控制块保存被管理指针和强引用计数，各个 Shared 只保存控制块地址。

a ─┐
   ├─→ Control { ptr, strong = 2 } ─→ Item
b ─┘
  • 空指针没有控制块，计数为 0。
  • 非空时 strong 等于共享该控制块的 Shared 数量。
  • 一次成功接管只产生一个控制块；对象和控制块都恰好释放一次。

下面的类型只用于理解机制：单线程、单对象、同类型拷贝，不提供数组、定制删除器、别名构造或 weak_ptr。被管理类型必须完整、可用 delete 销毁，析构不抛异常；不处理计数器达到极限的情况。

参考：标准共享所有权语义。

2. 拷贝、移动与赋值

操作怎样改变拥有者数量
操作控制块变化资源变化
从裸指针接管创建控制块，strong = 1接管独占释放责任
拷贝共享控制块，strong + 1不复制 Item
移动转移控制块指针，源置空不增加 strong
reset / 析构strong - 1；降到 0 时销毁控制块最后一个拥有者删除 Item
赋值先取得新所有权，再释放旧所有权旧资源可能在此刻销毁

赋值采用按值传参与 swap：构造临时参数取得新所有权，交换后临时参数持有旧资源，离开时自动释放。这样统一处理拷贝赋值、移动赋值和自赋值。

经典问题：为什么不能先删除旧指针，再复制新指针？

自赋值或双方本就共享资源时，可能提前销毁仍要使用的对象。先建立新所有权再交接，才能保持计数与资源有效性。仅复制裸地址还会造成两份“独占释放责任”。

3. 实现与异常安全

两次分配：调用者先创建 Item，Shared 再分配 Control。第二次分配失败时，局部 unique_ptr 会删除 Item；控制块成功建立后才 release 这份临时保护。

下载源码（examples.cpp）。使用 C++17 编译；断言测试请勿定义 NDEBUG。

完整实现与断言测试 
#include <cassert>
#include <cstddef>
#include <memory>
#include <utility>

// 教学版本：单线程、单对象、同类型共享；不支持数组和 weak_ptr。
template<class T>
class Shared {
    struct Control { T* ptr; std::size_t strong; };
    Control* control_ = nullptr;
    void release() noexcept {
        if (control_ && --control_->strong == 0) {
            delete control_->ptr;
            delete control_;
        }
    }
public:
    Shared() noexcept = default;
    explicit Shared(T* ptr) {
        if (ptr) {
            std::unique_ptr<T> guard(ptr);
            control_ = new Control{ptr, 1};
            guard.release();
        }
    }
    Shared(const Shared& other) noexcept : control_(other.control_) {
        if (control_) ++control_->strong;
    }
    Shared(Shared&& other) noexcept
        : control_(std::exchange(other.control_, nullptr)) {}
    Shared& operator=(Shared other) noexcept {
        swap(other);
        return *this;
    }
    ~Shared() { release(); }
    void swap(Shared& other) noexcept { std::swap(control_, other.control_); }
    void reset() noexcept { Shared{}.swap(*this); }
    T* get() const noexcept { return control_ ? control_->ptr : nullptr; }
    T& operator*() const { return *get(); }  // 前提：非空
    T* operator->() const noexcept { return get(); }
    explicit operator bool() const noexcept { return get() != nullptr; }
    std::size_t use_count() const noexcept {
        return control_ ? control_->strong : 0;
    }
};
struct Item {
    inline static int live = 0;
    int value;
    explicit Item(int v) : value(v) { ++live; }
    ~Item() { --live; }
};
int main() {
    Shared<Item> empty;
    assert(!empty && empty.use_count() == 0);
    {
        Shared<Item> a(new Item(7));
        Shared<Item> b = a;
        assert(a.get() == b.get() && a.use_count() == 2);
        a = a;  // 自拷贝
        assert(a.use_count() == 2);
        Shared<Item> c = std::move(b);
        assert(!b && c.use_count() == 2);
        c = std::move(c);  // 本实现的自移动保持原值
        assert(c && c.use_count() == 2);
        Shared<Item> d(new Item(9));
        d = a;  // 原来的 Item(9) 必须释放
        assert(Item::live == 1 && d.use_count() == 3);
        a.reset();
        c.reset();
        assert(d.use_count() == 1 && d->value == 7);
        d = empty;
        assert(Item::live == 0);
    }
    assert(Item::live == 0);
}

编译运行：g++ -std=c++17 -Wall -Wextra -pedantic examples.cpp -o shared-test。正常运行不输出内容，断言失败会终止。测试覆盖空值、共享计数、自赋值、自移动、替换旧资源、最后一个拥有者退出。自移动一行刻意覆盖边界，部分编译器会给出相应告警。

经典问题：能否用同一个裸指针构造两次 Shared？

不能。两个独立控制块会分别删除同一对象，产生重复释放。应复制已有 Shared。这个约束无法仅靠 get() 地址自动解决；生产接口优先使用标准库的 make_shared。

4. 标准 shared_ptr 的扩展

进一步需要解决的机制
能力设计要求
weak_ptr对象在强计数归零时销毁；控制块要保留到弱观察也结束。lock 需原子地“非零才增加”。
跨线程所有权不同 shared_ptr 实例共享控制块时，引用计数需同步；同一 shared_ptr 变量的读写与 Item 数据读写分别处理。
定制删除器 / 跨类型控制块保存正确的销毁操作，不依赖当前观察指针类型来猜。
别名构造被观察指针可指向子对象，被管理对象与返回的 get() 不一定相同。
make_shared常将对象与控制块放在一次分配中；弱引用残留时，对象已析构但合并分配的存储可能仍保留。
经典问题：把 strong 改成 atomic，是否就等价于 shared_ptr？

没有。还需证明最后一次释放、对象析构和控制块销毁的同步顺序；若支持 weak_ptr，还要解决 lock 与最后一次强释放之间的竞争。原子计数也不保护对象的数据。
