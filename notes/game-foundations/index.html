1. 帧同步与状态同步

同步的内容与本地职责
方案网络传什么关键约束
确定性锁步 / 帧同步按模拟 tick 编号的玩家输入或命令相同初始状态、输入和执行顺序必须产生相同模拟结果
状态同步权威状态快照或增量客户端处理插值、预测和状态校正；需控制快照带宽与频率

模拟 tick 与屏幕渲染帧不是同一个概念。锁步缺少某 tick 输入时可等待，或采用有明确规则的预测/回滚；状态同步常在两个快照间插值显示其他对象，以少量延迟换平滑。

预测与校正：本地先按输入预测移动；收到带确认序号的权威状态后回到对应状态，重放未确认输入，必要时平滑视觉误差。必须区分模拟正确性与显示平滑，不能只把位置强行拉近。

经典问题：帧同步为什么特别在意浮点与遍历顺序？

很小的数值或执行顺序差异可能随模拟放大，最终使各端状态分叉。固定步长、输入顺序、随机种子、容器遍历及数学实现都是确定性的一部分；相同源码不保证跨平台位级一致。

参考：确定性锁步设计 · Valve：网络、插值与预测。

2. 寻路：BFS、Dijkstra 与 A*

先把可行走空间建模成图：节点可表示网格格点、导航网格区域或路点；边表示可达关系，权重表示移动代价。障碍、转向、斜向移动和地形成本都会改变问题。

按边权选择算法
算法选择下一个节点保证前提
BFSFIFO 队列，按层扩展等权边的最少步数路径
Dijkstra最小已知距离 g非负边权，正确处理松弛与过期队列项
A*最小 f = g + hh 为剩余成本估计；最优性取决于启发式与重开策略

可采纳指 h 不高估到目标的真实最短代价；一致还要求每条边满足 h(u)≤cost(u,v)+h(v)，且 h(goal)=0。一致启发式允许常见图搜索在节点确定后不再重开；仅可采纳但不一致时，可能需要重新扩展已处理节点。

四方向、每步代价 1 的网格可用曼哈顿距离。若允许更便宜的斜向移动，原曼哈顿距离可能高估，应按移动模型换启发式。h=0 时 A* 退化为 Dijkstra。

A* 伪代码：允许更优路径重新入队

前提：有限图、非负边权，h 可采纳且 h(goal)=0。发现更优路径时允许重新入队，因此不要求启发式一定一致。

g[start] = 0，其他为无穷大
优先队列加入 (h(start), start, 0)
while 队列非空:
    弹出 (f, u, 入队时的 g)
    若入队时的 g != 当前 g[u]：跳过过期条目
    若 u 是目标：沿 parent 恢复路径并返回
    对每条可行边 u → v:
        candidate = g[u] + cost(u,v)
        若 candidate < g[v]:
            g[v] = candidate; parent[v] = u
            入队 (g[v] + h(v), v, g[v])
返回无路径
经典问题：第一次把目标放进队列就能结束吗？

通常不能。首次发现目标的路径未必最便宜；应按算法前提在目标作为当前最优条目被弹出时判断。还要处理不可达、起终点相同、过期队列项和斜向穿过障碍角的规则。

参考：Stanford CS221：A* 与一致性。

3. 二维旋转矩阵

约定使用列向量、x 向右、y 向上，绕原点做主动旋转，正角表示逆时针，角度单位为弧度。则：

[x′]   [ cosθ  −sinθ ] [x]
[y′] = [ sinθ   cosθ ] [y]

推导可看基向量：(1,0) 旋转后是 (cosθ,sinθ)，(0,1) 旋转后是 (−sinθ,cosθ)，两列组成矩阵。绕任意中心 c 旋转时先平移到原点，再旋转后平移回去：p′ = c + R(θ)(p−c)。

改为屏幕坐标 y 向下时，若仍用上述数值矩阵，正角在屏幕上看起来是顺时针。若要求正角仍是视觉逆时针，则使用 R(−θ)：第一行 cosθ、sinθ，第二行 −sinθ、cosθ。

经典问题：90° 旋转得到的 x 不是严格 0，是公式错了吗？

通常是浮点三角函数和运算舍入。用与量级匹配的绝对/相对容差检验，不直接判 double 相等。反复累计旋转可能积累误差；可从原始位置和累计角度重新计算，避免不断旋转上一步近似值。

4. 旋转实现与验证

下载源码（examples.cpp）。使用 C++17 编译；断言测试请勿定义 NDEBUG。

完整实现与断言测试 
#include <algorithm>
#include <cassert>
#include <cmath>
struct Point { double x,y; };
Point rotate_math(Point p,double radians) {
    const double c=std::cos(radians),s=std::sin(radians);
    return {c*p.x-s*p.y,s*p.x+c*p.y};
}
Point rotate_screen_ccw(Point p,double radians) {
    const double c=std::cos(radians),s=std::sin(radians);
    return {c*p.x+s*p.y,-s*p.x+c*p.y};
}
bool near(double a,double b) {
    return std::abs(a-b)<=1e-12+1e-10*std::max(std::abs(a),std::abs(b));
}
int main() {
    const double pi=std::acos(-1.0);
    const auto math=rotate_math({1,0},pi/2);
    assert(near(math.x,0) && near(math.y,1));
    const auto screen=rotate_screen_ccw({1,0},pi/2);
    assert(near(screen.x,0) && near(screen.y,-1));
    Point p{3,4};
    const auto q=rotate_math(p,0.73);
    assert(near(std::hypot(p.x,p.y),std::hypot(q.x,q.y)));
    const auto back=rotate_math(q,-0.73);
    assert(near(back.x,p.x) && near(back.y,p.y));
    auto cycle=p;
    for(int i=0;i<360;++i) cycle=rotate_math(cycle,pi/180);
    assert(near(cycle.x,p.x) && near(cycle.y,p.y));
}

验证数学坐标和屏幕坐标的方向、长度保持、逆旋转还原，以及多次小角度旋转。示例容差适用于这里的数值规模；碰撞和跨端确定性模拟需要各自明确的误差策略。
