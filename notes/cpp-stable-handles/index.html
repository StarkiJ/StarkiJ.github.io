vector 与稳定句柄

区分地址、位置和身份，处理扩容、重排、删除与槽位复用。

1. 引用失效与修复

vector 元素连续存储。增长导致重新分配时，原存储中的指针、引用与迭代器全部失效；没有重分配的尾部插入不使已有元素引用失效。不能根据“第几次 push_back”猜容量。

std::vector<int> v{1, 2, 3};
const auto position = std::size_t{0};
v.push_back(4);
std::cout << v[position]; // 扩容后重新定位；前提是位置语义没变
可选方案
方案适用前提代价与边界
先 reserve，再取得引用有可靠容量上界，期间不超限、不做使引用失效的操作提前占用空间；reserve 自身也可能重分配
保存下标，每次重新访问只追加，原位置始终代表同一业务对象删除、插入和排序会改变位置语义
vector<unique_ptr<T>>需要独立堆对象的稳定地址额外分配与间接访问；对象删除后借用指针仍悬垂
槽位 + generation 句柄连续数据需要增长、重排与删除额外映射和校验；不对外长期暴露地址
经典问题：如何稳定复现扩容失效，而不依赖某个实现的增长倍数？

先记录 capacity，填满到 size == capacity，再取得引用；下一次成功 push_back 必须扩容。错误版仅作为检测器样例运行；修复版在增长后重新查找，并断言对象值。不要把失效后的读值当作可预测输出。

参考：vector 失效规则。

2. 句柄与双向映射

句柄保存稳定槽位编号和版本号 generation；槽位表映射到当前密集数组下标；密集元素记录自己的槽位号，以便搬动后更新反向映射。

Handle { slot=7, generation=3 }
    → slots[7] { dense=2, generation=3 }
    → dense[2] { value, slot=7 }
  1. 查询：检查槽位存在、未删除、版本一致，再返回当前元素。
  2. 删除：用末尾元素覆盖被删位置，更新被搬元素的槽位映射，再弹出末尾。
  3. 失效：删除槽位的 generation 加一，并加入空闲链表。
  4. 复用：新对象取得该槽位的新版本；旧句柄因版本不符而失败。

查询与删除 O(1)，插入摊还 O(1)。删除采用 swap-and-pop，不保留密集数组的顺序；排序或重排必须同步维护映射。槽位表通常随历史同时存活对象数的峰值增长；达到版本上限后退役的槽位仍占空间，也会增加表长。

经典问题：为什么只有下标还不够？

删除后下标可能被另一个对象占用，旧 ID 会误认新对象。generation 区分“同一槽位的不同生命期”。计数器若回绕仍可能误认，因此示例到上限就退役槽位。

3. 实现与验证

示例只存 int，使搬动与删除不会因用户类型抛异常。新增元素分配失败时会回滚新槽位。泛型版本还需约束 T 的移动/交换，或设计异常后的映射恢复。

完整实现与断言测试 
#include <cassert>
#include <cstddef>
#include <cstdint>
#include <limits>
#include <stdexcept>
#include <utility>
#include <vector>

// Handle 只属于创建它的 Pool，不能跨 Pool 或跨 Pool 生命周期使用。
class Pool {
    static constexpr std::size_t none = std::numeric_limits<std::size_t>::max();
    struct Slot { std::size_t dense = none; std::uint64_t generation = 1;
                  std::size_t next = none; };
    struct Entry { int value; std::size_t slot; };
    std::vector<Slot> slots_;
    std::vector<Entry> dense_;
    std::size_t free_ = none;
public:
    struct Handle { std::size_t slot; std::uint64_t generation; };
    Pool() = default;
    Pool(const Pool&) = delete;
    Pool& operator=(const Pool&) = delete;
    Pool(Pool&&) = delete;
    Pool& operator=(Pool&&) = delete;
    Handle add(int value) {
        const bool fresh = free_ == none;
        const auto id = fresh ? slots_.size() : free_;
        if (fresh) slots_.push_back(Slot{});
        try { dense_.push_back(Entry{value, id}); }
        catch (...) { if (fresh) slots_.pop_back(); throw; }
        auto& slot = slots_[id];
        if (!fresh) free_ = slot.next;
        slot.dense = dense_.size() - 1;
        slot.next = none;
        return {id, slot.generation};
    }
    int* get(Handle h) noexcept {
        if (h.slot >= slots_.size()) return nullptr;
        const auto& s = slots_[h.slot];
        if (s.dense == none || s.generation != h.generation) return nullptr;
        return &dense_[s.dense].value;
    }
    bool erase(Handle h) noexcept {
        if (!get(h)) return false;
        auto& s = slots_[h.slot];
        const auto pos = s.dense;
        const auto last = dense_.size() - 1;
        if (pos != last) {
            dense_[pos] = dense_[last];
            slots_[dense_[pos].slot].dense = pos;
        }
        dense_.pop_back();
        s.dense = none;
        if (s.generation != std::numeric_limits<std::uint64_t>::max()) {
            ++s.generation;
            s.next = free_;
            free_ = h.slot;
        } // generation 达到上限后退役槽位，禁止回绕复用
        return true;
    }
    void swap_positions(std::size_t a, std::size_t b) {
        if (a >= dense_.size() || b >= dense_.size()) throw std::out_of_range("position");
        std::swap(dense_[a], dense_[b]);
        slots_[dense_[a].slot].dense = a;
        slots_[dense_[b].slot].dense = b;
    }
    std::size_t size() const noexcept { return dense_.size(); }
};
int main() {
    Pool pool;
    auto a = pool.add(10);
    auto b = pool.add(20);
    auto c = pool.add(30);
    for (int i=0; i<2000; ++i) pool.add(i);
    assert(*pool.get(a)==10 && *pool.get(b)==20 && *pool.get(c)==30);
    pool.swap_positions(0, 2);
    assert(*pool.get(a)==10 && *pool.get(c)==30);
    assert(pool.erase(b));
    assert(!pool.get(b) && !pool.erase(b));
    auto replacement = pool.add(99);
    assert(replacement.slot==b.slot && replacement.generation!=b.generation);
    assert(!pool.get(b) && *pool.get(replacement)==99);
    assert(pool.erase(a) && pool.erase(c));
    assert(!pool.get(a) && !pool.get(c));
    Pool one;
    auto only = one.add(1);
    assert(one.erase(only) && one.size()==0 && !one.get(only));
    assert(!pool.get({999999, 1}));
}

断言覆盖大量增长、显式重排、中间删除、末尾删除、重复删除、槽位复用和越界句柄。

4. 生命周期与并发边界

  • get 返回的是短期借用指针；下一次可能扩容、重排或删除的操作前必须停止使用。需要长期保存的是 Handle。
  • 句柄只在所属 Pool 的生命周期内有效。跨容器、存档或网络传输需要额外的容器身份与持久 ID。
  • 版本校验不解决并发：校验后另一线程仍可删除。须在同一把锁内完成查询与使用，或另行设计延迟回收。
  • 对象重排后应按句柄确认身份；仅检查地址是否相同不能证明指向同一个业务对象。
经典问题：稳定句柄是否让 T* 永远稳定？

没有。稳定的是访问对象的身份入口。每次通过句柄重新定位，并在受保护的访问期间使用临时指针，才避免持有旧地址。
